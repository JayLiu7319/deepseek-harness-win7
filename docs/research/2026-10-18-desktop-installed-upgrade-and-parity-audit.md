# Desktop 安装后启动修复、样式核对与剩余工作

目标固定为 `dsh-v0.1.5-rc.3` / `a4c74a91e06b00fe0b0937bde982170c526cc842`。本次修复候选为 `0cfbd91b`。此前 `228cfacc` 的完整资格只证明其冻结候选和精确发行包；隔离数据目录中的包内运行测试没有覆盖用户已有 `.dsh` 的安装升级。这次用户反馈暴露了该缺口，不能沿用旧回执宣称修复后的候选已经完整验收。

## 1. 启动错误与本机恢复

错误来自 `workspace` 启动时列举会话：默认 JSONL 后端使用 `zstd`，已有目录含明文 `session.jsonl`，因此按原版存储合同拒绝。不是 Windows 11 不支持，也不是安装包缺少 Python。上次截图中的 EPIPE 与本次编码冲突是两个问题。

本机只读检查发现 4 份可读取的 v0 明文会话和 8 份 v4 明文会话。rc.3 的当前格式为 v3；v4 保留原状，当前版本不会降级读取或回退到较旧代。显式选择 `none` 后，后端成功列出 4 份支持的会话。

已先备份桌面 patch，然后为当前安装版添加完整的匹配配置：

```yaml
- id: session-persistence-jsonl
  config:
    root: !!js dshHomePath('sessions')
    compression: none
```

本机备份位于 `%USERPROFILE%\.dsh\profiles\desktop\cordis.patch.pre-plaintext-recovery-20261018.yml.bak`。没有删除或转换历史会话。恢复后的实际已安装 x64 程序完成主界面、设置 RPC、工作区流、单实例和退出等 6 项检查。原安装程序的管理员交互由用户完成，本次没有据此补记自动安装验收。旧安装版退出时的一条 `Desktop Host is stopping` 日志独立保留。

源码修复只对 Desktop 的默认会话配置执行应用升级策略：默认目录只有明文历史且没有显式压缩配置时，在内存中沿用 `none`；空目录和压缩历史继续使用 `zstd`。显式配置、自定义根目录和混合编码仍按原合同处理。启动不改写用户 patch，不迁移历史文件。另将启动失败标题改用原版 locale，阻止启动未完成时第二个实例提前创建空白窗口，并结束退出后到达的晚请求。

## 3. 样式与交互核对

结论：**主应用和插件管理器复用了原版设计资源；不能据此认定整个 Desktop 已经实现逐像素和全部行为的 1:1 对齐。** 本次没有运行原版 Electron 44 桌面作同机像素比较。

| 部分 | 核对结果 | 边界或差异 |
|---|---|---|
| 主应用页面、字体、图标和组件 CSS | 234 份原版构建输入匹配；实际安装版正常显示 | Electron 22 使用已有兼容层；文件一致不能代替所有页面视觉验收 |
| 插件管理器布局和样式 | 原版 HTML/CSS/JS 三份逐字节一致 | 实际服务时替换输入 placeholder，locale 描述明确为本地 Python 包 |
| 插件窗口浅色/深色 | Electron 22 均实际打开并截图，原生系统字体和 Canvas 色生效 | `AccentColor` 不受支持，安装按钮回退为系统按钮色；需要与原版 Electron 44 同机核对，不能直接宣称该颜色已对齐 |
| 主窗口与插件窗口尺寸 | 主窗口 1280×840、最小 880×600；插件窗口 900×620，与原版相同 | Windows 原生边框、缩放与不同 Electron 版本仍影响最终像素 |
| 中文应用菜单与插件入口 | 单个“应用”菜单、插件入口和 Ctrl+, 与原版结构一致 | 报错截图中的 File/Edit/View 是提前创建窗口时的默认菜单；新源码阻止该初始化竞态 |
| 启动错误标题 | 新源码使用原版 locale 的 `startupFailed` | 仍采用原生错误框，不承诺跨 Electron 的原生控件像素一致 |
| 托盘与关闭按钮 | Win7 方案要求的托盘、恢复窗口、关闭后隐藏 | 原版没有这套托盘行为，最后窗口关闭时退出；这是明确的产品差异 |
| 插件安装、更新和移除 | 原版管理器 UI 配合 Python 插件事务 | 原版 npm 包/版本号与本版 Python 文件夹/ZIP 不同，不宣称 npm 插件 ABI 等价 |
| 低版本环境提示和离线指南 | Win7 方案新增，限定环境下显示 | 原版无此提示；额外界面不是原版样式证明 |
| 更新 UI | 保留原版 locale、renderer IPC 和 coordinator | Win7 使用独立签名完整安装器通道；未发布实际 feed |
| Standard/AIO 安装向导 | 本项目 NSIS 分发界面 | 属于 Win7 分发设计，不是原版 electron-builder 安装界面的复制 |

以上 Win7 分发差异遵循[既定桌面调研](2026-10-16-dsh-v0.1.5-rc3-desktop-distribution-evaluation.md)。其中研究文档的“100%同构/无任何现代 API 摩擦”应视为早期方案假设，不能当作实测结论；本次 `AccentColor` 观察已经说明必须逐项验证。
