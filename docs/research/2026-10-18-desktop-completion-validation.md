## 视觉检查的边界

Electron22/44 使用同一 Python Host 和固定原版 renderer，比较英文/中文、浅色/深色、1/1.25/1.5 模拟缩放下的主页面、设置、模型、模型编辑器和插件窗口，共 120 份视图。最终 `desktop-visual-matrix-20261018-h` 的完整矩阵通过窗口/控件观察、横向溢出、插件颜色、焦点和无脚本异常检查。60 对实际可见控件顺序、焦点、弹窗和披露区状态一致；主应用控件矩形最大差 `0.01043701171875` CSS px，插件原生表单控件最大差 2 CSS px。对照图与原始观察均保留。

进一步比较发现模型页的原生闭合 `details` 元素在 Chromium108 的 `getBoundingClientRect()` 仍返回内部输入尺寸，直接依此枚举可见控件会产生虚假的 Base URL 数量差异；观察器已按闭合披露区的实际可见性过滤。原失败和原图保留；中间 g 在 Electron44 首屏响应超时而失败，h 为独立新鲜完整运行，不与 g 拼接。插件原生表单控件有约 1–2 CSS px 的引擎度量差异；不通过更改原版应用资源来掩盖浏览器原生控件差异。

这不是上游 npm Host、原生 OS DPI、所有系统弹窗或任意插件 ABI 的逐像素认证。托盘、关闭隐藏、Python 插件包、NSIS 和独立更新通道是既定 Win7 分发设计的明确差异。
